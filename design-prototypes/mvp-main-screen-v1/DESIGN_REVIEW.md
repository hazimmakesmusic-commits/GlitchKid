# GlitchKid Vocal Lab: MVP main-screen design review (Phase 1)

Design only. Nothing in `Source/`, `Tests/`, `CMakeLists.txt`, presets or docs was changed for this phase. The prototype (`index.html` in this folder) is a static HTML/CSS/JS page: **it is not connected to the audio engine, processes no audio and analyses nothing.** Its spectrum and meters show either a fixed example frame or the idle state, and both are labelled as such on the page.

Labels used below: **FACT** (confirmed in source or tests), **PROPOSAL** (a design idea that needs engineering validation), **ASSUMPTION** (not established).

## 1. Audit

### VERIFIED IMPLEMENTED (source and tests)
| Area | What exists |
|---|---|
| Signal path | Pitch Tune → Formant → Harmony → Mutation → Doubler → 4-band EQ → CLEAN corrective → Compressor → CLEAN de-esser → Saturation → AIR LAB → Stutter → Echo → Dimension → Mix / Gain → Output Limiter (`processChunk`). Dry path delay-matched; Bypass is a 20 ms crossfade; the limiter acts on the dry path too. |
| Parameters | 69, all automatable through APVTS; IDs never renamed, new ones appended. Ranges and defaults are copied verbatim into the prototype. |
| Latency | 6 samples always (saturation oversampler); Pitch Tune ≈31 ms while on; Formant ≈21 ms while away from 0; Harmony the same as Pitch Tune while on; Limiter ≈1.5 ms while on. Reported to the host. |
| Stage switches | `tune_on`, `clean_on`, `air_on`, `echo_on`, `dim_on`, `dbl_on`, `lim_on`, plus Lab: `harm_on`, `mut_on`, `stutter_on` (Formant is "on" when ≠ 0). **No switch for the EQ, the compressor (1:1 = no effect), saturation (0 dB = clean) or Gain/Mix.** |
| Macros (`MacroEngine`) | TONE (eq_hi_gain −6…+6, eq_b2_gain −1.5…+1.5), PUNCH (comp_ratio 1…6 + threshold/attack/release/knee/capped makeup), SPACE (echo mix/fb/width, dim_mix, dbl_amount; toggles the three switches). Positions read back from one primary parameter. Tune styles NATURAL / LIGHT / HARD (strength + speed). Tested. |
| Presets | Factory Default + 8 starting profiles (overrides on Factory Default; generated by `tools/gen_profiles.py`; never set tuning, key, scale, Gain or Mix; levels calibrated by the generator). User presets as files in the user preset folder (macOS: `~/Library/Application Support/GlitchKid/Presets/User`), step prev/next, save (no silent overwrite), delete. |
| A/B | Two slots stored in the plug-in state (saved with the session), capture, recall, copy, "modified" flag. |
| Undo | One level: the sound before the last build, profile load, Beat Lock apply or Reference apply. |
| Build My Mix | Pure engine `automode::buildMix` returns the proposed sound plus a list of changes (id, from, to, reason), evidence and what was unavailable. **The UI applies the result immediately**, then offers BACK TO MY SOUND (undo) and WHAT CHANGED. Never changes tuning, key, scale, Gain or Mix. Switches the four Lab effects off. |
| Beat Lock | Needs a real Instrumental (sidechain) input; analyse → ticked suggestions → apply once → undo. Review-before-apply already exists here. |
| Reference Match | Local files only; bounded EQ proposals (eq_b1/b2/hi gains, ≤3 dB per move, ≤6 dB total, presence ≤ +4), review → apply ticked → undo. Formats verified by tests on Linux: WAV, AIFF, FLAC, Ogg Vorbis, MP3 (also recognised by content when the extension is wrong). M4A: macOS only, through CoreAudio; the test is gated to macOS; you reported it passing on your Mac in an earlier session (not re-run by me). Opus deliberately off. |
| Display data | Lock-free taps of the vocal input (before processing, L+R), the output (after the limiter, L+R) and the Instrumental input; message-thread FFT (2048 points, 96 log columns) and min/max waveform columns; input/output/beat peaks (louder channel); compressor gain reduction; limiter gain reduction; Pitch Tune detected and target note (only while Tune is on); CLEAN telemetry (rumble, mud dB, 3 resonance cuts, de-ess GR, seconds learned); Instrumental status (not connected / silent / live). |
| Window | Uniform scaling of one design size, 70–150 %, fixed aspect ratio (working tree: 1128 x 600; HEAD: 960 x 600). |
| Tests | Linux, this session: 407 test groups, 0 failures, CTest pass, VST3 built (working tree). |

### PARTIALLY IMPLEMENTED / LIMITED
* **Experimental effects (Formant, Harmony, Mutation, Stutter):** DSP, parameters and tests exist and they are in the signal path, but the current interface has no controls for them (an old session that has them on gets a warning). Build My Mix switches them off.
* **Build My Mix "propose, then apply":** the data for a review step exists (`changes` with reasons), but the UI applies first and undoes later; there is no per-change opt-out.
* **Stereo information:** the taps carry both channels, but no width or correlation value is computed for display.
* **Mac validation:** the floating-point fix and the shell are not yet validated on your Mac; FL Studio behaviour of the latest build is unverified.

### NOT IMPLEMENTED
* Reverb (none in the product; SPACE is delay plus width).
* Loudness (LUFS) metering, loudness matching for A/B or bypass, true-peak limiting (the limiter is sample-peak; worst-case overshoot measured at 3 dB).
* Key detection (Tune never detects the key).
* Per-stage bypass for EQ, compressor or saturation (no parameters).
* Preset categories, tags, favourites, search, rename in the plug-in.
* A dedicated Experimental Lab screen.

### UNKNOWN
* How the 8 profiles sound on real vocals (only calibrated numerically; no listening record in the repo).
* CPU cost with every Lab effect on at once inside FL Studio.
* Host behaviour at a new, larger design size (FL Studio window, Retina scaling).

### Answers to the verification questions
* **A. Effects that exist and work:** everything in the signal path above (each has a test file). Experimental ones are working but hidden.
* **B. Chain grouping without changing audio:** TUNE (Pitch Tune), CLEAN (Clean Lab), TONE (EQ, saturation, AIR LAB), DYNAMICS (compressor), SPACE (echo, dimension, doubler), FINISH (gain, mix, limiter). These are navigation groups only. Two of them are not contiguous in the real order (CLEAN is split around the compressor; the Doubler runs before the EQ), which the prototype states in its "exact signal order" note.
* **C. Safe macros:** the three existing macros (tested, bounded, read back). Single-parameter quick controls (Warmth = `sat_drive`, Clean = `clean_amount`, Output = `gain`) are safe because they are plain parameters. Any new multi-parameter macro is a PROPOSAL.
* **D. 15–20 presets:** the state format already holds every parameter, so more factory entries do not break compatibility (factory presets are code, not files; IDs are stable). Quality is the gate: 8 exist, none has a listening sign-off. See section 6.
* **E. Build My Mix:** it explains changes and is undoable, but it does not let you inspect before applying (section 7).
* **F. Visual data:** listed above. Not available: pitch curve over time (only the current note while Tune is on), LUFS, stereo correlation, per-stage spectra.
* **G. Reference Match formats:** WAV, AIFF, FLAC, Ogg Vorbis, MP3 (verified on Linux); M4A macOS only.
* **H. Window constraints:** one design size scaled uniformly, 70–150 %, fixed aspect; smallest text must stay readable at 70 %.
* **I. Must stay reachable:** every stage's parameters, presets (load, step, save, delete), A/B, DRY/PROCESSED, Undo, Build My Mix and What changed, Beat Lock, Reference Match, tuning key/scale/style, the hidden Lab effects (at least their off switches), MOTION preference.

## 2. Product hierarchy and user journey (PROPOSAL)
Two workspaces: **VOCAL** (default) and **EXPERIMENTAL LAB**. On VOCAL, the eye goes: chain → selected stage → signal → quick controls → guided start.
1. Open: a starting preset is shown in the top bar; the chain shows which stages are doing something.
2. Fast route: pick a preset or run Build my mix → review → apply.
3. Adjust: three quick controls, or open a stage from the chain for precise control.
4. Compare: A/B and DRY/PROCESSED in the top bar.
5. When inspiration hits: Experimental Lab.

## 3. Main-screen layout (PROPOSAL)
* **Top bar:** wordmark, VOCAL / EXPERIMENTAL LAB, preset field (‹ name ›, click opens the browser), Save, A/B with copy, DRY / PROCESSED, Undo, a latency chip (real value in the plug-in).
* **Chain (the anchor):** six compact nodes between IN and OUT peak meters. Each node: number, name, one-line job, a power switch only where a real switch exists (otherwise a dimmed placeholder explaining why), a status line derived from real parameters ("3:1", "flat", "2 of 3 on", "bypassed (dry)"), hatched when doing nothing. Selected node joins the panel below with a notch. Arrow keys move along the chain.
* **Selected-stage panel:** title, status, one-sentence purpose, grouped controls with real names, units, default on double-click, sub-switches per group, advanced controls behind a link (CLEAN trims), live read-outs where real data exists (Tune note, CLEAN telemetry).
* **Right column:** the signal display (input dashed violet, output pink with a scan-line fill), COMP GR / LIMITER / OUT PEAK bars, the three quick controls, Build my mix and the Lab entry.
* **Info line:** help for the control under the pointer and the Instrumental input status.
* Why: the chain is visible at all times and is also the navigation, so there is one way to find any control; the right column holds "fast" tools so they never push the precise controls around.

Gate for every entry (existing ones included): listened to on at least three real vocals (rap, sung, quiet), output peak below 0.95 and level within about 1 dB of the input, audibly distinct from its neighbours, and a one-line description that is true. **If fewer than 15 pass, ship fewer** (12–14 good presets beat 20 with duplicates). ## 7. Build My Mix: requirements and gaps
FACT: engine returns the proposal with reasons; UI applies at once; undo exists; it never touches tuning/key/scale/Gain/Mix.
Gaps for the proposed flow (Direction → Listen → Review → Apply ticked / Cancel):
1. Run `buildMix` without applying; hold the proposal in the editor.
2. Show the change list (already available) with tick boxes; apply only ticked items (new: apply a subset of a SoundState; Beat Lock already does this for its items).
3. Cancel leaves the sound untouched (trivial once step 1 exists).
4. Decide what happens if the user changes a control while the proposal is open (stale proposal: re-check or warn).
5. Tests: nothing changes before Apply; unticked items unchanged; undo restores exactly.
No DSP change is needed.

## 8. Visualisation data requirements
Available now (FACT): input and output spectra, waveform columns, peaks, compressor and limiter gain reduction, Tune detected/target note, CLEAN telemetry, Instrumental status.
The prototype uses only these. Would need new code: stereo width/correlation (computable from the existing taps on the message thread), a pitch-over-time trace (the detector value is only exposed as the current note), LUFS (new analysis), per-stage before/after spectra (new taps on the audio thread; avoid for the MVP).
Idle: nothing is drawn without a signal; the prototype has an "Idle" toggle to show it.

## 9. Accessibility, readability, resizing
* Text sizes in the prototype: 10–10.5 px for secondary labels at 100 %. At the 70 % minimum scale these become about 7 px: **too small**. Either keep 70 % only for a larger design size, or raise the smallest labels to 11.5–12 px. Engineering decision.
* Contrast: text #f0ecf5 and #a7a0b2 on #09080c–#15121b pass; the muted #6f6880 is for non-essential text only.
* Every interactive element is keyboard-reachable in the prototype (chain: arrow keys; knobs: arrow keys, double-click reset). JUCE needs the equivalent focus order and accessible names.
* State is never shown by colour alone: off stages are hatched and say "off"; disabled controls are dimmed and the info line says why.
* Proposed design size 1120 x 680 (the prototype frame). That is larger than today's 600 px height; it must be checked in FL Studio on a 13" laptop at 100 % and 70 %.

## 10. Deferred from the MVP
Experimental Lab screen design; Beat Lock and Reference Match placement (keep their current screens behind a "More" or a CONTEXT menu until redesigned); user-preset rename/favourites/tags; stage bypass for EQ/compressor; LUFS / loudness-matched A/B; true-peak limiting; drag-to-reorder chain (the audio order is fixed); animated decorative visuals.

## 11. Risks and open questions
* Beat Lock and Reference Match have no place on this main screen yet. Where do they live? (Suggestion: a compact "Context" menu in the top bar.)
* CLEAN and Doubler grouping differs from the real signal order; some users may care.
* Lab presets conflict with Build My Mix switching Lab effects off.
* A larger window may not suit small screens; aspect ratio change affects saved window sizes (if the host stores them).
* 18 proposed/existing presets with no listening record: the count may fall.
* The uncommitted working tree (determinism fix + shell) still needs your Mac validation and a decision before this redesign builds on it.

## 12. Recommended implementation phases
1. **Decide the base:** validate and commit (or drop) the current working tree on your Mac.
2. **Shell:** top bar + chain + stage panel + info line in JUCE, reusing existing controls and attachments (no parameter change); update UI tests.
3. **Stage panels:** move each stage's existing controls into the new panel; keep Beat Lock and Reference Match reachable.
4. **Build My Mix review step** (section 7) with tests.
5. **Preset browser** with categories and descriptions; listening pass on the 8 existing profiles.
6. **New presets** that pass the gate.
7. **Experimental Lab** screen (Formant, Harmony, Mutation, Stutter) and the Build My Mix rule for Lab effects.
8. Host validation in FL Studio on macOS at 70 / 100 / 150 %.
