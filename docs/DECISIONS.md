# Decisions log

Each entry: what was decided, why, and what was measured. Newest last.

1. **Framework: JUCE 9.0.4 + CMake + VST3 (macOS arm64 first).** Free to build with; closed-source commercial use needs the JUCE EULA (free Starter tier has a revenue/funding cap; terms for JUCE 9 were not verifiable from the build environment). Re-read https://juce.com/legal/juce-9-licence/ and confirm eligibility before any commercial release. JUCE is fetched by CMake at a pinned tag, never vendored. See LICENSES.md.
2. **No feature may be a decoration.** Every control maps to a parameter that changes audio; parameter IDs are permanent once released.
3. **"Off" means bit-exact.** The 0.1 dB parameter grid left ~9e-7 residue at "0 dB" on Apple Silicon (found by the Mac test run); gains/bands/makeup/mix within half a step of neutral are snapped to exactly neutral, and idle stages are skipped.
4. **Parameters smoothed over 20 ms** (gain, wet mix, EQ settings, drive); EQ coefficients refresh every 32 samples while moving.
5. **EQ:** own RBJ biquads in double precision (no allocation on the audio thread, no extra dependency).
6. **Compressor:** feed-forward, stereo-linked peak detector, soft knee, attack/release on the gain reduction (Giannoulis et al. 2012); default ratio 1:1 so a fresh instance is transparent. Attack/release are time constants (63% / 37%).
7. **Saturation anti-aliasing: 4x oversampling with JUCE's polyphase IIR half-band filters, not ADAA.** Measured against an ideal band-limited reference (aliasing, 10 kHz / 6 dB drive): plain tanh -27 dB, first-order ADAA -39 dB (and it dulls treble by up to 1.7 dB at 10 kHz), 4x IIR oversampling about -90 dB with flat response. A "linear part exact + ADAA on the residual" variant was rejected after it overshot badly (up to 3.7x full scale at 10 kHz).
8. **Constant 6-sample latency (0.125 ms @ 48 kHz), reported to the host.** The oversampler's latency is always present; the dry/bypass path and an idle saturation stage are delayed by the same amount so everything stays time-aligned. A linear-phase FIR oversampler would be phase-exact but costs 31-49 samples; rejected for now. Known consequence: blending dry with saturated audio (Mix < 100 %) can slightly colour the top octave (phase error 19 deg at 14 kHz, 81 deg at 18 kHz).
9. **Pitch correction is not started.** Separate feasibility gate per the master prompt.
10. **Process rule:** a Linux build and tests prove the code logic only; macOS behaviour is proven by the owner's Mac build, `ctest` and FL Studio. Tests are mutation-checked (deliberately broken code must fail them).
11. **Glitch Stutter = beat repeat of the slice before switch-on.** Captures the last N samples (N = rate at the tempo) from a continuously recorded history of the stage input; zero latency, no look-ahead, no feedback path, so output can never exceed the input peak. Own Mix so it can blend with live audio; at 0 % it is skipped and bit-exact. Seam is a crossfade into the pre-slice audio (continuous waveform), engage/release are 3 ms fades.
12. **Tempo: use the host's BPM, fall back to 120, say which.** The play head may be missing or return nothing/garbage; resolved once per block, clamped to 40..300 BPM, shown in the window. Phase is not locked to the host grid (loop starts at switch-on); host PPQ phase-lock is a possible later refinement (it would delay engagement to the next grid line).
13. **Test lesson:** a test that cannot fail is not a test. The first click test used a tone whose period divides the slice length exactly, so even a hard cut did not click; mutation checks exposed it and the test now uses a non-commensurate frequency.
14. **Non-finite audio never enters a recursive stage.** The EQ and the saturation oversampler hold IIR memory, so a single NaN/Inf used to poison all later audio (found in the project audit). Each stage zeroes non-finite input, and clears its own memory if it becomes non-finite or absurdly large; the plug-in is not muted. Chosen over muting/bypassing the whole plug-in because it leaves the rest of the chain and the dry path working. Mutation-checked: removing any of the four guards fails a test. See `ARCHITECTURE.md`.
15. **JUCE is pinned by commit, not tag.** `FetchContent` uses `3fb5cbc0340758596dac39f7c8de47d562b4896e`, which the upstream tag `9.0.4` resolves to; the fetched tree reports `project(JUCE VERSION 9.0.4)`. Tags can be moved; commits cannot.
16. **Liquid Echo design.** Placed after Glitch Stutter, before Output Gain; own Echo Mix (like Stutter), default off, zero added latency. Delay-time changes glide over 80 ms (click-free; the repeats bend in pitch while moving) rather than crossfading two taps, which is simpler and tape-like. Width is a right-channel time offset (1 + 0.5 x width) so mono vocals get stereo repeats with no level change (a mid/side width would do nothing to a mono vocal). Feedback is capped at 90 % in the DSP, with a low-pass and a 10 Hz DC blocker in the loop. Switching off cuts the tail (it does not ring out); tail length is not reported to the host.
17. **Dimension design.** After Liquid Echo, before Output Gain; own Mix, default off, zero latency. A dual modulated-delay (chorus) voice pair read from the high-passed mid signal and split into mid and side parts (Width = equal-power cross-fade), because a plain mid/side widener does nothing to a mono vocal and a single chorus voice pans it. The wet is L/R symmetric (no panning) and the side part cancels in mono, so Width 100 % is exactly mono-safe; lower Width trades some mono colouring (measured) for centred thickening. Wet gain capped at 0.6 after the first measurement at 0.4 widened too little (L/R correlation 0.88). No modulation-rate control: fixed incommensurate LFO rates avoid a periodic wobble and a rate knob would not improve the effect. Detune is a creative effect, not pitch correction.
18. **MOODS design.** A Mood is a data table applied through the normal parameter calls on the message thread (so the host sees automation and the DSP's own smoothing applies); no separate engine, nothing on the audio thread, no new saved state. Each Mood owns all 30 parameters of EQ, compressor, saturation, echo and Dimension so results never depend on the previous Mood; Output Gain, Bypass, Mix and Stutter are never touched (Stutter repeats captured audio and must stay a deliberate choice). The selected Mood is derived by comparing values, not stored, so it can never be stale. Compressor makeup is tuned per Mood from measurements so level on speech-like noise stays within 0.2 dB (Moods must not win by being louder). The Mood-switch click test was tightened after a first version failed to catch an unsmoothed parameter; it now uses a 30 Hz tone whose natural steps are tiny.
19. **MOODS 2.0 (supersedes 18).** The five first Moods were replaced by five Alter Egos plus a Mood Engine (Chaos, Blend, Surprise Me), because the product concept became "identities you can play". Same mechanism as before (data tables applied through the normal parameter system on the message thread, nothing on the audio thread, each identity owns the same 30 parameters, Output Gain/Bypass/Mix/Stutter never touched). New decisions: (a) **Blend is the existing main Mix**, not a new control, to avoid double-mixing and a second dry path; it replaced the left Mix knob in the UI and keeps its parameter ID. (b) **Chaos and Surprise are message-thread macros, not audio-thread parameters**, so the knobs always show what is audible and no unsafe cross-thread writes exist; the cost is that Chaos itself is not host-automatable (the underlying parameters still are). (c) The **selection is saved as three state properties** (alter ego id, Chaos, seed) that only restore the macro positions; restoring never re-applies an identity, so user edits and automation win; no new automatable parameter was added. (d) **Chaos is a table-driven linear move** of continuous parameters with per-parameter end values inside safe limits, switches never move; compressor makeup is part of the table and was tuned from measurements so level stays within 0.65 dB. (e) **Surprise is an allowlist with per-parameter jitter and hard limits and an integer xorshift generator**, so it is reproducible on every platform; it never varies rhythm, switches, dynamics or level. (f) **Glitch Stutter is in no Alter Ego** (it repeats captured audio and must remain a deliberate choice). (g) **Morph deferred** (needs interpolation rules per parameter type and a rule for switches and the echo division). The old `MoodTests` were ported, not removed.
