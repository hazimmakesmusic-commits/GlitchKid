# Decisions log

Each entry: what was decided, why, and what was measured. Newest last.

1. **Framework: JUCE 9.0.4 + CMake + VST3 (macOS arm64 first).** Free to build with; closed-source commercial use needs the JUCE EULA (free Starter tier has a revenue/funding cap; terms for JUCE 9 were not verifiable from the build environment). Re-read https://juce.com/legal/juce-9-licence/ and confirm eligibility before any commercial release. JUCE is fetched by CMake at a pinned tag, never vendored. See LICENSES.md.
2. **No feature may be a decoration.** Every control maps to a parameter that changes audio; parameter IDs are permanent once released.
3. **"Off" means bit-exact.** The 0.1 dB parameter grid left ~9e-7 residue at "0 dB" on Apple Silicon (found by the Mac test run); gains/bands/makeup/mix within half a step of neutral are snapped to exactly neutral, and idle stages are skipped.
4. **Parameters smoothed over 20 ms** (gain, wet mix, EQ settings, drive); EQ coefficients refresh every 32 samples while moving.
5. **EQ:** own RBJ biquads in double precision (no allocation on the audio thread, no extra dependency).
6. **Compressor:** feed-forward, stereo-linked peak detector, soft knee, attack/release on the gain reduction (Giannoulis et al. 2012); default ratio 1:1 so a fresh instance is transparent. Attack/release are time constants (63% / 37%).
7. **Saturation anti-aliasing: 4x oversampling with JUCE's polyphase IIR half-band filters, not ADAA.** Measured against an ideal band-limited reference (aliasing, 10 kHz / 6 dB drive): plain tanh -27 dB, first-order ADAA -39 dB (and it dulls treble by up to 1.7 dB at 10 kHz), 4x IIR oversampling about -90 dB with flat response. A "linear part exact + ADAA on the residual" variant was rejected after it overshot badly (up to 3.7x full scale at 10 kHz).
8. **Constant 6-sample latency (0.125 ms @ 48 kHz), reported to the host.** The oversampler's latency is always present; the dry/bypass path and an idle saturation stage are delayed by the same amount so everything stays time-aligned. A linear-phase FIR oversampler would be phase-exact but costs 31-49 samples; rejected for now. Known consequence: blending dry with saturated audio (Mix < 100 %) can slightly colour the top octave (phase error 19 deg at 14 kHz, 81 deg at 18 kHz).
9. **Pitch correction is not started.** Separate feasibility gate per the master prompt. (Superseded by 20 and 21: built and in the plug-in.)
10. **Process rule:** a Linux build and tests prove the code logic only; macOS behaviour is proven by the owner's Mac build, `ctest` and FL Studio. Tests are mutation-checked (deliberately broken code must fail them).
11. **Glitch Stutter = beat repeat of the slice before switch-on.** Captures the last N samples (N = rate at the tempo) from a continuously recorded history of the stage input; zero latency, no look-ahead, no feedback path, so output can never exceed the input peak. Own Mix so it can blend with live audio; at 0 % it is skipped and bit-exact. Seam is a crossfade into the pre-slice audio (continuous waveform), engage/release are 3 ms fades.
12. **Tempo: use the host's BPM, fall back to 120, say which.** The play head may be missing or return nothing/garbage; resolved once per block, clamped to 40..300 BPM, shown in the window. Phase is not locked to the host grid (loop starts at switch-on); host PPQ phase-lock is a possible later refinement (it would delay engagement to the next grid line).
13. **Test lesson:** a test that cannot fail is not a test. The first click test used a tone whose period divides the slice length exactly, so even a hard cut did not click; mutation checks exposed it and the test now uses a non-commensurate frequency.
14. **Non-finite audio never enters a recursive stage.** The EQ and the saturation oversampler hold IIR memory, so a single NaN/Inf used to poison all later audio (found in the project audit). Each stage zeroes non-finite input, and clears its own memory if it becomes non-finite or absurdly large; the plug-in is not muted. Chosen over muting/bypassing the whole plug-in because it leaves the rest of the chain and the dry path working. Mutation-checked: removing any of the four guards fails a test. See `ARCHITECTURE.md`.
15. **JUCE is pinned by commit, not tag.** `FetchContent` uses `3fb5cbc0340758596dac39f7c8de47d562b4896e`, which the upstream tag `9.0.4` resolves to; the fetched tree reports `project(JUCE VERSION 9.0.4)`. Tags can be moved; commits cannot.
16. **Liquid Echo design.** Placed after Glitch Stutter, before Output Gain; own Echo Mix (like Stutter), default off, zero added latency. Delay-time changes glide over 80 ms (click-free; the repeats bend in pitch while moving) rather than crossfading two taps, which is simpler and tape-like. Width is a right-channel time offset (1 + 0.5 x width) so mono vocals get stereo repeats with no level change (a mid/side width would do nothing to a mono vocal). Feedback is capped at 90 % in the DSP, with a low-pass and a 10 Hz DC blocker in the loop. Switching off cuts the tail (it does not ring out); tail length is not reported to the host.
17. **Dimension design.** After Liquid Echo, before Output Gain; own Mix, default off, zero latency. A dual modulated-delay (chorus) voice pair read from the high-passed mid signal and split into mid and side parts (Width = equal-power cross-fade), because a plain mid/side widener does nothing to a mono vocal and a single chorus voice pans it. The wet is L/R symmetric (no panning) and the side part cancels in mono, so Width 100 % is exactly mono-safe; lower Width trades some mono colouring (measured) for centred thickening. Wet gain capped at 0.6 after the first measurement at 0.4 widened too little (L/R correlation 0.88). No modulation-rate control: fixed incommensurate LFO rates avoid a periodic wobble and a rate knob would not improve the effect. Detune is a creative effect, not pitch correction.
18. **MOODS design.** A Mood is a data table applied through the normal parameter calls on the message thread (so the host sees automation and the DSP's own smoothing applies); no separate engine, nothing on the audio thread, no new saved state. Each Mood owns all 30 parameters of EQ, compressor, saturation, echo and Dimension so results never depend on the previous Mood; Output Gain, Bypass, Mix and Stutter are never touched (Stutter repeats captured audio and must stay a deliberate choice). The selected Mood is derived by comparing values, not stored, so it can never be stale. Compressor makeup is tuned per Mood from measurements so level on speech-like noise stays within 0.2 dB (Moods must not win by being louder). The Mood-switch click test was tightened after a first version failed to catch an unsmoothed parameter; it now uses a 30 Hz tone whose natural steps are tiny.
19. **MOODS 2.0 (supersedes 18).** The five first Moods were replaced by five Alter Egos plus a Mood Engine (Chaos, Blend, Surprise Me), because the product concept became "identities you can play". Same mechanism as before (data tables applied through the normal parameter system on the message thread, nothing on the audio thread, each identity owns the same 30 parameters, Output Gain/Bypass/Mix/Stutter never touched). New decisions: (a) **Blend is the existing main Mix**, not a new control, to avoid double-mixing and a second dry path; it replaced the left Mix knob in the UI and keeps its parameter ID. (b) **Chaos and Surprise are message-thread macros, not audio-thread parameters**, so the knobs always show what is audible and no unsafe cross-thread writes exist; the cost is that Chaos itself is not host-automatable (the underlying parameters still are). (c) The **selection is saved as three state properties** (alter ego id, Chaos, seed) that only restore the macro positions; restoring never re-applies an identity, so user edits and automation win; no new automatable parameter was added. (d) **Chaos is a table-driven linear move** of continuous parameters with per-parameter end values inside safe limits, switches never move; compressor makeup is part of the table and was tuned from measurements so level stays within 0.65 dB. (e) **Surprise is an allowlist with per-parameter jitter and hard limits and an integer xorshift generator**, so it is reproducible on every platform; it never varies rhythm, switches, dynamics or level. (f) **Glitch Stutter is in no Alter Ego** (it repeats captured audio and must remain a deliberate choice). (g) **Morph deferred** (needs interpolation rules per parameter type and a rule for switches and the echo division). The old `MoodTests` were ported, not removed.
20. **Pitch-correction prototype (Stage 4.1), in-house, isolated.** YIN detector + scale quantiser + TD-PSOLA-style shifter, no dependency: the strongest ready-made options are GPL (Rubber Band, aubio) or unverified (SoundTouch) and unusable or unproven in a closed-source product; MIT options (Signalsmith Stretch, sevagh/pitch-detection) exist but were not needed. The code lives in `Source/Experimental/` and is compiled only into the test target and the optional `PitchLab` harness, so the plugin binary, parameters and GUI are untouched. Per-sample processing (not blocks) so output is independent of host block size. Latency is constant at 2.5 x the longest period (31 ms at 80 Hz lowest pitch) because that is what guarantees every grain is complete when cut; lowering it means raising the lowest tracked pitch. Findings: octave errors 0 and median error under 2.5 cents on synthetic voices; the first tests missed a wrong scale bit and the level check initially mis-read the expected spectral-envelope effect of up-shifting (both fixed in the tests, not the code). Quality on a real voice is unknown until the owner's listening test.
21. **Pitch Tune in the plug-in (Stage 4.2).** First stage in the chain (so everything after it works on the tuned voice), default off, five parameters (`tune_on/key/scale/strength/speed`), stereo and mono, one shifter per channel driven by one detection on the channel average so the stereo image cannot move. **Latency is reported only while Tune is on** (6 samples off, 6 + 1504 at 48 kHz on) instead of always: "off adds nothing and stays bit-exact" was kept as the rule, and a vocal-effects plug-in whose main selling point (Alter Egos) does not need tuning should not delay every user by 31 ms. Cost of that choice: switching changes the latency the host sees (reported by a 10 Hz message-thread timer, never from the audio thread, so the host may re-align a moment after the click), and the audio is crossfaded for 20 ms between the straight-through signal and the delayed tuned signal; the dry (Mix/Bypass) path is delayed by the same extra amount through the same ramp so it stays aligned. While off, the corrector still records the last ~30 ms (`feed`, about 1 % of a core) so switching on has no silent gap. A shifter that moves in whole periods can sit up to half a period away from the reported latency; it re-anchors at each voiced onset, which keeps a steady note within a few samples (measured 0). Rejected: always-on constant latency (simpler, but forces 31 ms on everyone and rewrites the "6 samples" contract used by all existing tests); a per-note UI "target" lock and formant control (later). The five parameters are never touched by Alter Egos, Chaos or Surprise. Defaults: key C, chromatic, strength 100 %, speed 20 ms.
22. **Formant shifter (Stage 4.3): STFT cepstral envelope warping, in-house, isolated, independent of Pitch Tune.** The formants (spectral envelope) move; the harmonics do not, because the module multiplies each STFT frame by a REAL gain (warped envelope / original envelope): no phase is touched, so the fundamental is preserved by construction (measured 0.09 cents worst over 60 cases). Chosen over PSOLA grain resampling (needs a pitch period every instant; buzzes on unvoiced sounds and "s"; would couple it to the pitch tracker) and LPC pole shifting (root-finding, unstable time-varying filters, locks onto single harmonics on high voices: the metallic/hollow artifacts the brief warned about). Stereo uses one gain from the channel-average power spectrum so the image cannot move. Own 60-line radix-2 FFT because JUCE's FFT takes a spin-lock and the audio path must be lock-free. Per-sample processing, so output never depends on the block size; constant latency frameSize - 1 (1023 samples, 21-23 ms at 44.1-96 kHz; 2047 at 88.2/96 kHz); neutral skips the transforms and is exact to 3e-8. **What measuring changed:** the first version (fixed 1 ms envelope smoother) improved the envelope only from 6.7 to 4.2 dB error; a pitch-adaptive smoother and "true envelope" passes got 2.2 dB but produced hop-rate modulation sidebands (inharmonic energy as high as -1 dB re total at high pitch and -12 semitones), found with a spectrum dump, not by ear. The shipped design trades detail for stability (20 % per-frame gain smoothing, lifter tightening from 90 % of the pitch period below 130 Hz to 50 % above 220 Hz): 2.9 dB envelope error, inharmonic energy mean -42.6 dB / worst -28.4 dB. A 60 dB spectrum floor was tried and removed: no test could tell it from nothing (the mutation survived) and measurement showed no benefit. Known weakness kept visible in the tests: at 300 Hz the harmonics are too sparse to locate a narrow formant. Level is held within +-12 dB of compensation (measured within 1.7 dB). Not integrated at that point; integrated in 23 after the owner's listening test.
23. **Formant in the plug-in (Stage 4.4): one parameter, same switching design as Pitch Tune.** After the owner's listening test of the Stage 4.3 prototype on one real vocal (+3, -3, neutral) passed, `FormantShifter` moved to `Source/DSP/FormantShifting/` and became `formant_shift` (-12..+12 semitones, step 0.1, **default 0**), labelled FORMANT in the window (the technical term, chosen over "voice size"). It sits after Pitch Tune and before the EQ and works with or without Tune. **0 means off**: anything within half a step of 0 is exactly neutral, adds no latency and the output stays bit-exact (the "6 samples" contract and all older tests are untouched); away from 0 it adds `FormantShifter::latencyFor` (21-23 ms) to the reported latency (message-thread timer, never the audio thread) and to the dry path, with a 20 ms crossfade between the straight-through and the delayed signal, so Mix and Bypass stay time-aligned; with Pitch Tune also on the delays add (about 53 ms at 48 kHz). **While idle the shifter still runs at 0 semitones on a scratch copy and the result is discarded** (cost about 0.15 % of a core: neutral frames skip the transforms): that keeps its overlap-add full so moving the knob off 0 has no fade-in or dip, which is simpler than adding a separate "listen only" mode like Pitch Tune's `feed`. At prepare time the shifter starts at 0 and glides (30 ms) to a restored non-zero value, so a loaded session fades the effect in rather than starting mid-way. Rejected: a combined "voice" control with Pitch Tune (they are independent and Formant is useful alone); a separate window row (the window is already 980 px tall; FORMANT shares the row and the note read-out moved under the ON switch). Verified by tests, including: plug-in output == standalone module delayed by 6 samples, bit for bit; Mix 0 / Bypass give the dry input delayed by the total latency, bit-exact, with Formant alone and with Pitch Tune; NaN/Inf equal zeros always-on and while crossfading; zero allocations per block with both on. Not verified: FL Studio behaviour of the changing latency with two effects, real-voice quality beyond the owner's single test, voices above about 250 Hz.
24. **Vocal Mutation (Stage 4.5): a single-sideband frequency shifter / ring modulator, in-house, zero latency.** The brief asked for robotic/alien/harmonically altered textures that are not "another saturator". tanh already exists and keeps a harmonic voice harmonic (measured: 100 % of the power stays at multiples of the fundamental), so a second harmonic generator would duplicate it. A frequency shifter adds the same number of Hz to every partial and breaks the harmonic series (measured: 0.0 % at multiples after a 110 Hz shift of a 220 Hz voice). Chosen over: ring modulation alone (one sound only; it is the middle of the Character knob), a vocoder / granular or spectral freeze approach (needs an FFT stage with latency and a much larger design), a pitch shifter (already exists in Pitch Tune; keeps harmonics), formant shifting (already exists). **Hilbert transform:** the all-pass-pair design was chosen over a linear-phase FIR because it adds no latency, so Mix, Bypass and the host latency report need no change (a FIR would have added a third latency-switching stage like Pitch Tune and FORMANT). The coefficients I first remembered from memory did NOT give 90 degrees (checked numerically before use: the phase difference between the two chains was nowhere near constant), so new ones were designed by least squares and verified in the time domain: unwanted sideband at most -41.1 dB over 44.1/48/88.2/96 kHz x 300/1000/5000 Hz. **Controls:** MUTATION (carrier 600 Hz x m^2, wet fades in over the first 3 % so 0 is exact), CHARACTER (DOWN - ROBOT - UP, a continuous sideband morph with level compensation, so it changes the sound not the volume), BLEND (own wet/dry; the global Mix is also there but it also affects every other stage, which is not what "how much mutation" means). Defaults: off; 40 / 50 / 100 when switched on. **Not done, on purpose:** the carrier is not locked to the sung pitch or to the Pitch Tune key (inharmonic is the point, and locking needs the pitch detector which would couple two modules); no MOODS integration yet (a later step); no oversampling (alias products are only the last fc Hz below Nyquist). **Tests:** 22 groups, 15 deliberate breaks caught (one initially survived: the processor not clearing Mutation memory in a settled Bypass; a test was added). Synthetic signals only: the sound on real vocals has not been judged.
25. **MOODS + Mutation, presets and A/B (Stage 4.6).** **Mutation in MOODS:** Alter Egos now own the four `mut_*` parameters, with a per-value `active` flag so an identity can leave a parameter alone. THE CLONE does not use Mutation, but still switches it OFF: the alternative (leaving `mut_on` unaffected, as literally asked for parameters without a sensible mapping) would let the robotic setting of THE PARASITE leak into a "Clone", which breaks the principle that an identity does not depend on the previous one (decisions 18/19); the three values it has no mapping for are left alone. Surprise Me was not extended to Mutation (preserves its behaviour). Mappings follow the Mutation design (decision 24): CELESTIAL slow UP shimmer, VOIDWALKER DOWN undertone, THE PARASITE ROBOT, ALTERED STATE UP. Compressor makeup was re-tuned by measurement because a dry/wet blend of two different signals is 0.7-1.7 dB quieter. **Preset format:** our own small XML (plain units, `formatVersion`), not a dump of the APVTS XML, so it does not depend on JUCE's internal state layout and stays readable; chosen over JSON because JUCE reads and writes XML natively (no dependency). **Sound state, not state tree:** a preset and an A/B slot are `SoundState` copies of the parameters; the parameters stay the only live source of truth. **Bypass is not part of a sound** (a performance switch: recalling A while comparing against the dry signal would otherwise flip it) - a deliberate deviation from "all parameters". **Atomicity:** applying a sound is a sequence of ordinary single-parameter changes, not one atomic swap, because the audio code reads each parameter directly; every intermediate mixture is legal and smoothed, and a true atomic swap would need a double-buffered parameter bank (a much larger change) - not done. **A/B model:** explicit capture (SET A/B) rather than the usual "edits go into the active slot", because the brief requires that switching never changes a stored slot; the cost is that an unsaved edit is lost when you switch (it is flagged with `*`). A/B lives in the plug-in state so it survives a DAW save; presets are files. **Preset load policy:** keep both snapshots, clear the active marker. **Found while testing:** NaN/Inf in the input could pass through the dry copy used by Bypass and Mix < 100 % and re-emerge up to 1023 samples later (FORMANT's delay); fixed at the root by zeroing non-finite input once per block (finite audio is bit-identical). **Not done:** factory presets beyond the Factory Default (the Alter Ego buttons already are the factory sounds), preset folders / categories / import-export, renaming a preset, A/B on MIDI/host parameters other than the sound parameters, undo.
26. **Vocal Doubler and Harmony (Stage 4.8).** **Audit first:** Dimension (decision 17) is a fixed-delay (9/13 ms), sine-modulated chorus with a high-passed wet and its own mix; it is not a doubler (no timing control, periodic modulation, no low end). So the Doubler is a new, different effect, and the two can be used together. **Doubler design:** delayed copies (the brief allowed a delayed copy as one component), made less artificial by independent aperiodic delay wander (pitch wobble = delay change rate, scaled to the DETUNE setting), a low-pass, and centre/side placement. Chosen over PSOLA-shifted doubles: those would give a true static detune but add 31 ms of latency to a "thickening" effect, add grain and need a pitch tracker on every voice; a delay-based double adds no latency and works on unvoiced sounds and noise. The cost is that DETUNE is a wobble around the original pitch, not a fixed offset, and that it is plainly a synthetic double. No separate Blend: DOUBLE (amount) already is the wet/dry of the doubled voices, and the global Mix blends the whole chain. **Harmony design:** reuse, not duplicate: `PitchCorrector` got an optional fixed-interval mode (default off, tested bit-exact against the old behaviour), so detection, voiced hold and the PSOLA shifters are Pitch Tune's own. **Fixed interval only, nine named intervals, no key/scale:** a scale-aware third needs the sung note's place in a key and smooth interval changes at note edges; the Pitch Tune quantiser could supply the first, but doing it unproven would risk claiming scale-correct harmony that is not, so the brief's fallback (a clearly labelled fixed-interval prototype) was taken. Direction is in every interval name (UP / DOWN) to keep it unambiguous. **One voice, voiced gate:** PSOLA of noise buzzes and a doubled "s" lisps, so the voice is faded out when unvoiced (measured -227 dB on noise). **Latency:** Harmony adds Pitch Tune's delay only while on, with the same crossfade and dry-path alignment as Pitch Tune and FORMANT; the Doubler adds none. **MOODS:** the Doubler is driven by three Alter Egos (switched off by the other two so a setting cannot leak, as for Mutation); the Harmony is not, because Alter Egos must never change the reported latency. **Found while testing:** the first Harmony gate was refreshed per host call, so tiny blocks differed from large ones (fixed: a fixed 64-sample grid, update after the chunk); and the harmony settings were built in two places, which let a deliberate break survive (fixed: one function). **Not done, on purpose:** more than one harmony voice, scale-aware thirds, per-voice pan/detune, a humanise/vibrato mode for the Harmony, true static detune for the Doubler.
